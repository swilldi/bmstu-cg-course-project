# PLAN — чек-лист по этапам курсовой

Этапы и что от них ожидается в РПЗ и презентации — по методичке
`../../КР_КГ_ПримерПроцессаРазработкиПО.pdf`, §2. Даты с диаграммы Ганта там — формальность,
единственная жёсткая точка — защита на 15–17 неделе. 🤖 отмечает, где уместно позвать
агента (и только ревью/явная рутина, не реализация).

## 0. Постановка (до этапа анализа)

- [ ] Не менее четырёх задач, по одной минимум на каждый из этапов ниже.
- [ ] Введение РПЗ по этим двум пунктам.

      (производительность, память, визуальное правдоподобие, простота параметризации под

- [ ] Аналитический раздел РПЗ + вывод «были выбраны алгоритмы...».

## 3. Технологический этап

Реализация — сам, по модулям из `ARCHITECTURE.md`, в этом примерно порядке. Баланс
движок/вручную — не деталь реализации, а условие приёмки, см. `ARCHITECTURE.md` →
«Кто что делает» и `REVIEW.md` перед каждым пунктом ниже, где он применим.

- [ ] `Terrain`: карта высот → `SCNGeometry` средствами SceneKit, декоративный материал.
- [ ] `SceneObject` × 5: первый объект — стандартное тело SceneKit + материал, полигональная
      аппроксимация через параметр тесселяции примитива. 🤖 после одобрения первого — по
      явной просьбе клонировать паттерн для оставшихся четырёх (это и есть допустимая
      агенту рутина).
- [ ] `AuroraSynthesis`: протокол + одна выбранная на этапе анализа реализация.
- [ ] Аврора-нода: `SCNProgram`, ray march по `AuroraGrid` с интегрированием
      излучения/поглощения — полностью свой шейдер, движок только планирует draw call.
- [ ] Custom lighting-model modifier: направленный свет (тень — от `SCNLight.castsShadow`,
      использование тени — своё) + Blinn-Phong своими руками + подсветка сиянием через
      сэмплы-пробники. Проверить, что модификатор подключён и к ландшафту, и ко всем пяти
      объектам — иначе тени не будут согласованы по сцене.
- [ ] `CameraController`: узел камеры + `SCNCameraController`/`allowsCameraControl`.
- [ ] `ParameterStore` + SwiftUI-панель: текстовые поля на все пользовательские параметры
      из `SPEC.md`.
- [ ] Ручное прохождение сценариев: смена всех параметров вживую, включая крайние значения
      (0 занавесов, 8 занавесов, максимальная сетка).
- [ ] Технологический раздел РПЗ (обоснование средств, примеры кода, UI, сценарии
      тестирования) + вывод «было реализовано ПО...».
- [ ] Слайд со средствами разработки и структурой ПО.
- 🤖 ревью после каждого модуля по `REVIEW.md`.
