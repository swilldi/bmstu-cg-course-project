# REVIEW — чек-лист для агента

Формат замечания: `[уровень] файл:строка. что/почему/однострочный фикс`. Уровни: blocker
(нарушает ТЗ, требование руководителя по балансу движок/вручную или архитектурную границу)
/ warning / nit.

## Баланс движок/вручную (требование руководителя, проверять первым)

См. `ARCHITECTURE.md` → «Кто что делает». Нарушение любого пункта — всегда `[blocker]`,
это не стиль, а условие приёмки работы.

- [ ] Ландшафт и пять объектов сцены — геометрия через SceneKit (`SCNGeometry` /
      `SCNSphere`/`SCNBox`/...), это допустимо и ожидаемо, не нужно переделывать вручную.
- [ ] Камера — через SceneKit (узел камеры + `SCNCameraController`/`allowsCameraControl`),
      тоже ожидаемо.
- [ ] Материалы ландшафта и объектов НЕ используют стандартную модель отражения SceneKit
      (`SCNMaterial.lightingModel` из коробки без кастомизации) — подключён собственный
      custom lighting-model shader modifier.
- [ ] Тень допустимо получать от движка (`SCNLight.castsShadow`), но то, как тень входит в
      итоговый цвет пикселя, — код в собственном modifier, а не то, что движок посчитал бы
      сам по умолчанию.
- [ ] У источника света явно выставлен `shadowMode = .forward` (это дефолт с macOS 10.10,
      но должен быть виден в коде, а не подразумеваться) — иначе тень не попадёт в
      `_light.intensity` внутри lighting-model modifier и подсветка сиянием/тень
      рассинхронизируются.
- [ ] Синтез сияния, объёмный рендер сияния и подсветка сцены сиянием — целиком в
      собственном коде (`AuroraSynthesis`, `SCNProgram`, тот же custom lighting-model
      modifier), нигде не переложены на готовые средства SceneKit.

## Соответствие ТЗ (жёсткие ограничения, не мнение)

- [ ] Занавесов не больше восьми.
- [ ] Цвет занавеса задан раздельно для нижней/средней/верхней частей.
- [ ] Расчётная сетка не больше 256×256×128 узлов.
- [ ] Объектов на сцене не меньше пяти, все — стандартные тела с полигональной
      аппроксимацией (не импортированные меши).
- [ ] Поверхности матовые (диффузная составляющая доминирует), но зеркальная
      составляющая присутствует в модели освещения, а не убрана «для простоты».
- [ ] Источник света на бесконечности один: направление + цвет + интенсивность —
      пользовательские, не хардкод.
- [ ] Тени от направленного источника действительно строятся (не просто затемнение).
- [ ] Коэффициенты отражения поверхностей и коэффициенты излучения/поглощения светящейся
      среды — вводятся пользователем на этапе выполнения, а не константы в коде.
- [ ] Камера управляется мышью, параметры сцены и наблюдателя — ещё и текстовыми полями.
- [ ] Сияние действительно влияет на освещение сцены (виден цветной отсвет на
      террейне/объектах), а не только рисуется как отдельный слой поверх.

## Архитектурная граница (см. `ARCHITECTURE.md`)

- [ ] Смена активной реализации `AuroraCurtainSynthesizing` требует правки только внутри
      модуля `AuroraSynthesis` — ничего в аврора-ноде (`SCNProgram`), `Scene`, GUI не
      должно знать о конкретном типе стратегии.
- [ ] `AuroraGrid` остаётся единственным интерфейсом между синтезом и рендером —
      никаких «побочных» полей, которые читает рендер напрямую из конкретной стратегии.
- [ ] Список объектов сцены — данные (массив описаний), не россыпь ручных вызовов
      конструкторов по всему коду.

## Производительность

- [ ] На сетке 256×256×128 (≈8.4M узлов) нет наивного полного CPU-прохода каждый кадр
      без крайней необходимости — это либо GPU (Metal), либо явно обоснованная причина.
- [ ] Шаг интегрирования ray march — параметр, а не захардкоженная константа, и его
      изменение реально видно по времени кадра (иначе исследование бессмысленно).

## Код-стиль (Swift + Metal)

- [ ] Никаких `!`, `try!`, `as!` без комментария, почему это безопасно.
- [ ] `@Observable`, не `ObservableObject`.
- [ ] Metal buffers/textures не пересоздаются каждый кадр без необходимости.
- [ ] Нет retain-циклов в замыканиях render loop (delegate/completion handlers).
- [ ] Новых зависимостей нет — если появились, спросить, а не молча добавить в Package
      resolved.

## Границы роли агента

- [ ] Правка не добавляет фичу и не меняет архитектурное решение — только рутинное
      повторение уже одобренного паттерна или собственно ревью.
- [ ] Файлы в `docs/` не тронуты.
- [ ] Ничего не закоммичено агентом.
